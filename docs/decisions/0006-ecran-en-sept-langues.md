# ADR-0006 — L'écran parle sept langues, avec le système de traduction du Tab5

> **English summary.** The screen and the settings page speak seven languages: French (the source language and the
> only one reviewed by the author), English, German, Dutch, Spanish, Italian and Turkish. As on the Tab5 (gettext
> style), the French text written in the code is the key; there is one flat YAML file per language in `i18n/`; a Python
> generator writes a sorted C++ table for the pure core (testable on the PC) and one small JSON file per language for the
> settings page. Fallback: requested language, then English, then French. The language index stored in NVS never changes
> (fr 0, en 1, de 2, nl 3, es 4, it 5, tr 6). The screen language and the assistant language are two separate settings.
> **The six translations were written by an AI; no native speaker has read them.**
> Done and checked on the PC only, with no board: the core and its tests (mutation-tested), the settings page in seven
> languages (119 Playwright checks, all green), and a check of the embedded font (no glyph missing for the seven
> languages). **Not verified**: how long German and Dutch texts fit on the real screen, how TinyTTF draws ç ğ ı İ ö ş ü on
> the board, the wake words, the quality of the translations. Status: the principle was decided by the author on
> 06/11/2026; every detail below marked « proposé » is not yet confirmed by him or on a board.

- **Statut** : principe **décidé par Axel le 06/11/2026** (« écran 7 langues, vu qu'on a les bases ») ; réalisé côté PC le 06/11/2026 (branche `depot-langues`, aucune carte) ; ce qui touche la carte reste **proposé**, à confirmer à la phase 2.
- **Contexte** : le firmware ESPHome du Tab5 parle déjà français (langue source), anglais, allemand, néerlandais, espagnol, italien et turc, avec un système de type gettext éprouvé : le texte français écrit dans le code est la clé, un fichier YAML plat par langue, un générateur qui produit les tables, anglais en repli. Source : `docs/translations.md` du dépôt Tab5 (lu le 06/11/2026).
- **Décision** :
  - Mêmes sept langues, même principe : `tr("texte français")`, un fichier par langue `i18n/<code>.yaml` (`"texte français": "traduction"`), un script Python (`components/core/outils/generer_i18n.py`) qui génère une table C++ (comme `generer_fuseaux.py`), repli sur l'anglais puis sur le français. **L'indice de langue enregistré en NVS ne change jamais** : fr 0, en 1, de 2, nl 3, es 4, it 5, tr 6 (l'ordre du sélecteur du Tab5) ; on ajoute une langue à la fin.
  - `tr()` vit dans le **noyau pur** (`components/core/include/ecran/i18n.hpp`, C++ standard, sans ESP-IDF ni LVGL) donc testable sur le PC ; les tests vérifient que chaque clé existe dans chaque langue ou retombe sur le repli, et que `%d`/`%s` et `{noms}` sont conservés dans le même ordre.
  - La table est triée par octets UTF-8 et interrogée par dichotomie ; une clé inconnue est rendue telle quelle (le texte français), jamais une chaîne vide.
  - La **page de réglages** parle les mêmes langues : un petit fichier JSON par langue (`web/app/lang/<code>.json`, `GET /lang/<code>.json`, public) chargé à la demande, pas de texte français en dur dans `app.js` (chaque texte est un identifiant de `i18n/page.yaml`). La page suit la langue de l'écran ; le repli est la langue demandée, puis l'anglais, puis le français.
  - La langue de l'**écran** et celle de l'**assistant vocal** sont deux réglages distincts (`langue_ecran`, `langue_assistant`, français par défaut l'un et l'autre) ; la reconnaissance, la synthèse et la consigne du LLM suivent la seconde. Le champ « langue » du service de reconnaissance vocale disparaît du contrat (`docs/api-reglages.md` §6, §7 et §13).
  - Les phrases que l'appareil renvoie par son API (erreurs, préréglages) sortent dans la **langue de l'écran**, depuis les mêmes fichiers `i18n/<code>.yaml`.
  - **Tutoiement** partout dans les six langues traduites (comme sur le Tab5) ; le français garde le vouvoiement de ses textes actuels.
  - L'attribution **Open-Meteo (CC BY 4.0, lien vers open-meteo.com)** est visible dans la page, traduite avec la langue de la page.
  - Les traductions sont écrites par une IA (Claude) depuis le français et l'anglais, comme dans le dépôt Tab5 ; le français seul est relu par l'auteur ; c'est dit dans `i18n/README.md`.
- **Réutilisation** : le vocabulaire commun existe déjà dans `Tab5/lang/*.yaml` (jours, mois, libellés météo…) : repris tel quel pour les clés identiques plutôt que retraduit (jours, mois, « Redémarrer », « Orage », « Brouillard », « Pluie faible », « Pluie modérée »…). Les clés du Tab5 propres à Home Assistant, aux jeux et au réveil ne sont pas reprises. L'agent `traducteur` du dépôt Tab5 fait ce travail pour ses fichiers ; sa consigne est à adapter.
- **Constaté le 06/11/2026** (PC seulement : Windows 11, ESP-IDF et cartes non utilisés ; *Vu sur* : branche `depot-langues`, aucune carte) :
  - **Contenu** : 285 clés dans chacune des six langues traduites (90 pour l'écran : dates, météo, « Bonjour » ; 133 pour la page de réglages ; 62 pour l'API et les préréglages) et 138 identifiants de page. Octets de texte : 6 834 pour les clés françaises, de 5 872 (anglais) à 6 971 (allemand) pour chaque traduction, 45 627 au total. Calcul, **non mesuré** (aucune compilation ESP-IDF) : une ligne de table = 7 `string_view` de 8 octets sur RISC-V 32 bits, soit 15 960 octets pour 285 lignes ; avec les 45 627 octets de texte (plus un octet de fin par chaîne, si le compilateur en ajoute un), de 61,6 à 63,6 Ko en flash.
  - **Tests du noyau** (`test/host/test_i18n.cpp`, compilés et exécutés sous ASan et UBSan par `test/host/lancer.py`, mode « complet ») : 17 tests à la compilation plus une vérification à l'exécution de la langue courante ; ils couvrent l'ordre figé des indices, l'indice NVS hors limites (retombe sur le défaut), la table triée sans doublon, l'UTF-8 valide, les clés présentes dans chaque langue, les marqueurs identiques et dans le même ordre, le vocabulaire du Tab5, le repli en → fr → clé, et les libellés météo, jours, mois, textes « Bonjour » et messages de l'API dans les sept langues. `test/host/controle_i18n.py` ajoute des contrôles croisés sans compilation (sources cohérentes et sorties générées à jour ; textes « Bonjour » de `main/` = table = copie du test ; page et faux appareil sans texte français hors table).
  - **Mutations** (`test/host/mutations_i18n.py`) : 27 mutations de `i18n.hpp` et de `i18n_donnees.inc` (sur 233 au total dans `lancer.py`), chacune doit faire échouer le test visé. Résultat de `python test/host/lancer.py --mutations` : « 233 mutations, 0 problème(s) » ; chacune des 27 est détectée par le test visé. La vérification de la langue courante à l'exécution (`std::atomic`) n'est pas couverte par une mutation.
  - **Page de réglages** : parcours Playwright (Chromium, rendu téléphone) contre le faux appareil : **119 vérifications, toutes OK, code de sortie 0** (49 avant ce travail). Pour chacune des sept langues : onglets et titres dans la langue, aucun identifiant brut affiché, aucun texte français visible dans les six autres, libellé météo de la table WMO traduit, pas de défilement horizontal à 360 px ; repli anglais puis français quand les fichiers manquent ; attribution Open-Meteo traduite avec son lien ; au départ seul `fr.json` est demandé.
  - **Poids** (réponse gzip du faux appareil, niveau 9) : page 14 750 octets (`index.html` 1 037, `style.css` 2 409, `app.js` 11 304) ; fichier de langue de 2 067 octets (`en`) à 2 338 octets (`de`) ; page avec l'allemand, la plus lourde : 17 088 octets, pour un budget de 30 720.
  - **Polices** : `main/assets/roboto_700.ttf` (Roboto Bold, 927 caractères dans la `cmap`, SHA-256 identique à `main/assets/README.md`) contient **tous** les caractères des sept langues, lus avec fontTools 4.66.1 par `components/core/outils/verifier_glyphes.py` : les textes de l'écran (90 par langue), les lettres propres à chacune (turc : ç ğ ı İ ö ş ü, capitales Ç Ğ Ö Ş Ü et â î û ; allemand : ä ö ü ß, Ä Ö Ü et ẞ ; espagnol : ñ Ñ ¿ ¡ et les voyelles accentuées ; italien : à è é ì ò ù et capitales ; néerlandais : ë ï é è ê ö ü et ĳ ; français : à â ä ç é è ê ë î ï ô ö ù û ü ÿ œ æ et capitales), les guillemets « » et l'apostrophe ’, le « ° ». **Liste des glyphes manquants : vide.** La présence dans la `cmap` ne dit pas comment TinyTTF dessine ces caractères sur la carte.
- **Risques et points non vérifiés** :
  - **Rendu des accents sur la carte** : un glyphe présent dans la police peut encore mal s'afficher (TinyTTF, hauteur de ligne, crénage du turc). À constater sur l'écran du Tab5 ; **non vérifié**.
  - **Longueur des textes** : l'allemand et le néerlandais sont plus longs que le français ; la page tient à 360 px dans les sept langues (vérifié au PC), mais **aucun écran de l'appareil n'a été vu** dans ces langues : chaque écran est à contrôler sur la carte. Les libellés météo ne dépassent pas 34 caractères dans aucune langue (budget de conception, pas une mesure d'écran).
  - **Qualité des traductions** : écrites par une IA, relues par personne. Les contrôles prouvent que les marqueurs sont intacts, que rien ne manque et que l'encodage est valide ; ils ne prouvent ni qu'une phrase est juste ni qu'elle sonne naturellement. Un locuteur de chaque langue doit relire avant publication.
  - **Mot d'activation** : « Bonjour ESP » est français. Les mots d'activation disponibles pour les autres langues et leur licence : **non vérifié** (recherche 06). Tant que ce n'est pas tranché, la langue de l'assistant vocal peut différer de celle de l'écran.
  - **Attribution Open-Meteo sur l'écran de l'appareil** : la page de réglages la porte ; l'écran de l'appareil non (hors du périmètre de ce travail). La formulation exacte exigée par la licence CC BY 4.0 reste « non précisée » dans `docs/recherche/03` ; à trancher avec Axel avant publication.
  - **Côté appareil** : la route `GET /lang/<code>.json`, le service des fichiers déjà compressés et la lecture de la langue en NVS ne sont écrits que dans le contrat (`docs/api-reglages.md`) et dans le faux appareil ; le firmware ne les implémente pas encore.
  - **Autres navigateurs** : la page n'a été essayée que dans Chromium.
- **Conséquences** : la phase 2 (écran principal) et la phase 3 (page de réglages) portent les sept langues dès le départ ; aucun texte d'écran n'est ajouté sans passer par `tr()` (règle déjà dans `AGENTS.md`) ; ajouter un texte demande la ligne dans les six fichiers de langue (voir `i18n/README.md`). `verifier_glyphes.py` est à relancer à chaque ajout d'une langue ou d'une police.
- **Mise à jour du 11/11/2026** (lot « textes et traductions », PC seulement, aucune carte) : (1) **un seul chemin de traduction** : les tables locales (`visuel_textes.hpp`, `grandeurs.hpp`, `vigie_textes.hpp`, `mer_textes.hpp`, les jours courts de `visuel_dates.hpp`, `main/textes_1b.h`) sont ramenées dans `i18n/*.yaml`, leurs fonctions ne sont plus que des noms de `i18n::tr` ; l'écran de diagnostic est traduit ; (2) **clés à contexte** `"contexte|texte"` pour un mot français à plusieurs sens (« vent|faible », « jour court|mer ») ; le contexte ne s'affiche jamais ; les 19 formes courtes du Tab5 (« Dim »… « Déc ») et deux phrases que plus rien n'affichait sont retirées ; (3) les **`{noms}`** peuvent changer d'ordre dans une traduction (ils sont remplacés par leur nom), les `%…` gardent le leur ; (4) **registre** confirmé et contrôlé : le français vouvoie, les six autres langues tutoient. Détail : `i18n/README.md`.
