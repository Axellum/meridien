La police est rendue à l'exécution par TinyTTF (LVGL) : tout le Latin-1 (accents, « ° ») est disponible sans sous-ensemble à préparer. Les polices intégrées de LVGL s'arrêtent à l'ASCII.

Les icônes sont lues en place, dans la flash (`main/ui_meteo_icones.cpp` bâtit leurs descripteurs LVGL sans copier les pixels) : 0 octet de RAM pour les pixels. Le binaire est embarqué par `target_add_binary_data()` dans `main/CMakeLists.txt` (symboles `_binary_icones_meteo_bin_start` et `_end`).

**`mdi_roue.ttf` est un fichier modifié** au sens de l'Apache-2.0 (§ 4 b) : c'est un sous-ensemble de la police d'origine, où tout le reste (des milliers de glyphes, les tables de substitution, les noms sauf la famille et la version) a été retiré avec `fontTools.subset` ; les contours des 3 glyphes sont ceux d'origine, non redessinés. Aucun fichier `NOTICE` n'a été trouvé à la racine du dépôt d'origine (liste complète des fichiers : non vérifiée) ; la table de noms de la police ne porte pas de ligne de copyright. Les polices d'icônes ne servent qu'à la roue d'appui long (ADR-0019) ; les icônes météo restent les dessins originaux de `icones_meteo.bin` (ADR-0008). Le binaire est embarqué par `target_add_binary_data()` (symboles `_binary_mdi_roue_ttf_start` et `_end`) et rendu par TinyTTF, comme Roboto ; chaque icône est un caractère privé (plan 15) : si le glyphe manquait, l'écran afficherait un rectangle vide, ce que `--verifier` et le rendu PC (`tools/rendre.ps1 -Scene roue`) empêchent.
