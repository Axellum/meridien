# Météo, heure, page de réglages, calendrier — recherche du 06/11/2026

> **Summary (EN)** — Research note of 2026-11-06 on weather, time, the embedded settings page and the calendar (three web-research agents plus three command checks marked "vérifié").
> - Weather: Open-Meteo for forecast and geocoding, no API key. Free for non-commercial use only (rate limits listed in the note); licence CC BY 4.0 (the note did not find the wording of the required credit). The complete request measured 2,839 bytes raw (996 gzip). Refresh every 15–30 min, NVS cache, "stale" mention when offline. Both APIs answer with `access-control-allow-origin: *` (checked with curl). The Tab5 repository has no WMO code table: it must be written.
> - Time: SNTP plus an embedded IANA-name → POSIX-string table (posix_tz_db, MIT, about 461 lines); keep the last time zone in NVS.
> - Settings page: SoftAP + captive portal on the C6 (not shown to work on P4 + C6; ESP-IDF's captive-portal example does not list the P4), served by `esp_http_server` over local HTTP (self-signed HTTPS discouraged), stable `<name>.local` address through mDNS, secrets in encrypted NVS (the HMAC scheme consumes an eFuse block permanently), a light front end, a geocoding proxy in the firmware (a phone on the SoftAP often has no internet), OTA with rollback.
> - Calendar (version 2): Google's device OAuth flow does not allow Calendar scopes and test-mode authorisations expire after 7 days, so the plan is the calendar's secret iCal (ICS) address (ADR-0004); freshness is 6–24 h according to third-party sources (no Google source), and an ICS parser on a microcontroller must be tried on a real calendar.
> - Alternatives to Open-Meteo (MET Norway, OpenWeatherMap, WeatherAPI, Pirate Weather, Tomorrow.io, others) are listed with their key and free-tier limits.

Sources : 3 agents de recherche web + 3 vérifications faites par commande le 06/11/2026 (marquées **vérifié**).

## 1. Météo : Open-Meteo

**Conclusion** : Open-Meteo pour la météo et le géocodage (pas de clé, un seul appel couvre tout). Voir ADR-0003.

- **Conditions** (open-meteo.com/en/terms, /pricing) : gratuit **non commercial** : < 600 appels/min, 5 000/h, 10 000/jour, par IP et par application (le tableau de prix ajoute 300 000/mois, non appliqué pour l'instant). Licence CC BY 4.0 (formulation d'attribution non précisée). Pas de garantie de disponibilité sur le gratuit. Usage commercial (abonnement, publicité) = plans payants Standard/Professional/Enterprise, **prix non publiés**. La domotique personnelle y est citée comme non commerciale. → Un projet public non commercial est dans le cadre ; **vendre l'écran changerait la donne**.
- **Requête minimale utile** : `current=temperature_2m,apparent_temperature,is_day,weather_code,wind_speed_10m,wind_direction_10m,wind_gusts_10m,pressure_msl,relative_humidity_2m` + `hourly=temperature_2m,weather_code,precipitation_probability,uv_index` avec `forecast_hours=48` + `daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset,uv_index_max,precipitation_probability_max` avec `forecast_days=7` + `timezone=auto` + `timeformat=unixtime`.
- **Taille mesurée (vérifié)** : **2 839 octets bruts, 996 octets en gzip** pour cette requête complète (l'estimation de l'agent, 5 à 8 Ko, était trop haute). Peu de mémoire, cJSON suffit.
- **Rafraîchissement** : toutes les 15 à 30 min avec un décalage aléatoire ; cache en NVS avec horodatage ; afficher « périmé » en cas d'échec ; backoff exponentiel sur 429 et 5xx ; HTTPS par `esp_crt_bundle_attach` (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE`, bundle issu de Mozilla NSS ; compatibilité avec `esp_http_client` à vérifier dans sa doc).
- **Géocodage** (`geocoding-api.open-meteo.com/v1/search`) : `name`, `count` (1-100), `language=fr`, `countryCode` ; réponse avec `latitude`, `longitude`, `timezone` (nom IANA), `country`, `admin1`, `population`, `postcodes`. **Recherche par préfixe**, insensible à la casse et aux accents, sans flou : 1 caractère → rien, 2 → nom exact, ≥ 3 → préfixe. Déclencher à 3 caractères avec anti-rebond. Exemple (vérifié) : « Lyon » → `Europe/Paris`, 45,749 / 4,848.
- **CORS (vérifié)** : l'API de géocodage **et** l'API de prévision répondent `access-control-allow-origin: *` (GET, OPTIONS) → le navigateur peut les appeler directement. La doc ne le dit pas : constat par `curl -D -`.
- **Codes météo WMO** (doc Open-Meteo ; libellés français = traduction de l'agent, la doc est en anglais) : 0 ciel dégagé · 1 plutôt dégagé · 2 partiellement nuageux · 3 couvert · 45 brouillard · 48 brouillard givrant · 51/53/55 bruine légère/modérée/dense · 56/57 bruine verglaçante légère/dense · 61/63/65 pluie faible/modérée/forte · 66/67 pluie verglaçante légère/forte · 71/73/75 neige faible/modérée/forte · 77 grains de neige · 80/81/82 averses de pluie faibles/modérées/violentes · 85/86 averses de neige faibles/fortes · 95 orage · 96 orage avec petite grêle · 97 orage violent · 99 orage avec forte grêle. Les 96 et 99 ne sortent que de certains modèles : prévoir un repli sur 95. Jour/nuit : `is_day` (0/1) choisit soleil ou lune pour les codes 0 à 2.
- **Alternatives** (clé, gratuité, limites) : MET Norway (pas de clé, User-Agent obligatoire, < 20 req/s, coordonnées à 4 décimales, CC BY 4.0) ; OpenWeatherMap One Call 3.0 (clé, 1 000 appels/jour gratuits puis 0,0014 €/appel) ; WeatherAPI (clé, 100 000/mois, 3 jours) ; Pirate Weather (clé, 10 000/mois) ; Tomorrow.io (clé, 500/jour) ; Bright Sky/DWD (centré Allemagne, non adapté) ; Météo-France AROME (GRIB lourds, inadapté à l'ESP32) — mais ses modèles passent par Open-Meteo avec `models=` (option exacte non vérifiée). Repli possible plus tard : MET Norway.
- **Dépôt Tab5 existant** : la tablette n'appelait jamais Open-Meteo, Home Assistant le faisait ; il n'y a **aucune table WMO** dans le dépôt Tab5 (seulement une table d'états texte HA → glyphes). À écrire.

## 2. Heure et fuseaux

- **SNTP** : `esp_netif_sntp_init()` avec `ESP_NETIF_SNTP_DEFAULT_CONFIG("pool.ntp.org")`, puis `esp_netif_sntp_sync_wait()` ; `setenv("TZ", posix, 1); tzset();`. `pool.ntp.org` convient à toutes les zones.
- ESP-IDF n'embarque pas la base IANA. **Table IANA → chaîne POSIX** : `nayarsystems/posix_tz_db` (**MIT**, `zones.csv` généré depuis `/usr/share/zoneinfo`, ~461 lignes ; `Europe/Paris` → `CET-1CEST,M3.5.0,M10.5.0/3`). Solution la plus propre : embarquer `zones.csv` (~20 Ko, estimation) en flash avec recherche binaire sur le nom IANA ; le régénérer à chaque version ; repli sur `utc_offset_seconds` si le nom est inconnu. Piège : certaines zones sont de la forme `<-03>3`, à tester avec newlib. Alternative écartée : composant `qb4-dev/tzdata` (50 téléchargements, table figée).
- **Garder le dernier fuseau en NVS** (leçon du dépôt Tab5, ADR-0020) : sinon le réveil sonne à une mauvaise heure sans réseau.

## 3. Page de réglages embarquée

**Conclusion** : voir ADR-0003.

1. **Première mise en service** : SoftAP sur le C6, portail captif (DNS joker + option DHCP 114), page servie par `esp_http_server`. L'exemple ESP-IDF `captive_portal` liste ESP32, C2, C3, C5, C6, C61, S2, S3 — **pas le P4** ; esp_hosted 3.0.x liste le P4 comme hôte pour un exemple SoftAP. **Portail captif via esp_hosted P4+C6 : aucune source ne le démontre** → à prototyper. Option 114 : disponibilité dans la version d'IDF non confirmée. Alternative : saisie sur l'écran tactile + QR code vers la page. `wifi_provisioning` pour le P4 : page de doc introuvable (404), non vérifié.
2. **mDNS** : adresse stable `<nom>.local` après la première connexion.
3. **Serveur HTTP** : `esp_http_server` (3 sockets réservés en interne, `max_open_sockets`, `lru_purge_enable`, WebSocket via `CONFIG_HTTPD_WS_SUPPORT`). **HTTPS auto-signé déconseillé** : ~40 Ko de RAM par socket, première session TLS ≥ 2 s, avertissement navigateur qui dégrade « la belle page » → HTTP local protégé par un **jeton d'appairage affiché sur l'écran**.
4. **Secrets** : NVS chiffré (XTS-AES). Deux schémas : basé sur la flash encryption, ou basé sur le périphérique HMAC (clé dérivée d'un eFuse, sans flash encryption sur le P4, mais **consomme un bloc eFuse, définitivement**). Les clés API ne sont jamais renvoyées en clair par l'API (masquées), ni exportées.
5. **Frontend** : Preact ou JS vanille + CSS moderne, gzip, en partition LittleFS ou dans le binaire (`svelteesp32` : 142 Ko gzip pour 458 Ko dans son exemple ; `thorrak/esp_wifi_config` : Preact, LittleFS 512 Ko, < 100 Ko visés). Aucun comparatif chiffré de frameworks trouvé : mesurer sur notre build. Développement contre un faux serveur sur PC. Pages de WLED, Tasmota, ESPHome web_server v3, OpenBeken, Shelly : **non consultées**, le « ce qui les rend claires » reste à faire. Accessibilité, mobile d'abord, thème sombre/clair : bon sens, pas de source.
6. **Géocodage — piège** : pendant le SoftAP, le téléphone n'a souvent pas Internet et bascule sur ses données mobiles. Deux issues : (a) géocoder après le passage sur le Wi-Fi domestique (le navigateur appelle Open-Meteo, CORS vérifié) ; (b) **proxy dans le firmware** (`/api/geocode?q=`), qui marche aussi pendant la mise en service et évite toute dépendance au navigateur. Retenu : (b) comme chemin principal, voir ADR-0003.
7. **Mise à jour** : `esp_ota_*` (begin/write/end/set_boot_partition) pour le téléversement par la page ; 2 slots OTA + partition `ota` de 0x2000 ; rollback par `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` + `esp_ota_mark_app_valid_cancel_rollback()` ; `esp_ota_begin()` échoue tant que l'application en cours est en attente de validation ; anti-rollback = 16 incréments d'eFuse au plus. **Secure Boot v2 (RSA-3072 ou ECDSA) à reporter** : irréversible (eFuses), une révocation agressive peut rendre l'appareil inutilisable, USB-OTG de la ROM désactivé.
8. Pièges : Android/iOS ouvrent parfois le portail dans un navigateur restreint ; les commandes Wi-Fi d'esp_hosted circulent **non chiffrées** (identifiants) ; téléversement OTA à limiter en taille et protéger par le jeton ; export JSON sans clés en clair.

## 4. Calendrier Google (phase 2)

**Conclusion** : voir ADR-0004. L'OAuth « appareil » ne marche pas pour Calendar ; on prend l'**adresse secrète iCal (ICS)**.

- **Device flow** (developers.google.com/identity/protocols/oauth2/limited-input-device) : scopes autorisés `email`, `openid`, `profile`, `drive.appdata`, `drive.file`, `youtube`, `youtube.readonly`. **`calendar.readonly` et `calendar.events.readonly` n'y sont pas.**
- **Écran de consentement** : en mode « Testing » (externe), **les autorisations expirent après 7 jours**, jetons de rafraîchissement compris ; 100 utilisateurs de test au plus. Application non vérifiée avec scopes sensibles/restreints : plafond de **100 nouveaux utilisateurs à vie** ; vérification requise. Si Calendar est « sensible » ou « restreint » : non confirmé (la console le marque à l'ajout). 100 jetons de rafraîchissement par compte et par client OAuth. → Pour un projet ouvert, chaque particulier devrait créer son propre projet Cloud (irréaliste) ou passer par une vérification Google à client_id partagé (inférence).
- **CalDAV Google** : OAuth obligatoire, Basic = 401 → écarté. **Calendrier public** : à déconseiller.
- **ICS secret** (support.google.com/calendar/answer/37648) : lien en lecture seule, révocable (« Reset »). **Fraîcheur : aucune source Google ; sources tierces 6 à 8 h en moyenne, jusqu'à 12-24 h (non vérifié)** — hors de notre contrôle, à annoncer à l'utilisateur. Taille, limites de débit et plafond d'événements non trouvés. Le lien est un secret en clair → NVS chiffré. Les administrateurs de comptes pro peuvent désactiver ce partage. iCloud, Outlook, Proton, Nextcloud : non recherchés.
- **Analyse d'un ICS sur microcontrôleur** : `uICAL` (C++11, MIT, flux filtré pour économiser la mémoire, cas RRULE connus passants) ; rien n'indique EXDATE, VTIMEZONE/TZID ni ESP32 (exemples UTC/ESP8266), maintenance non vérifiée ; libical : pas de port ESP32 trouvé. Pièges classiques : événements « toute la journée » (`VALUE=DATE`), récurrences avec exceptions, fuseaux. **Tester avec un vrai agenda.** Compromis : relais facultatif auto-hébergeable (ICS → JSON), parseur embarqué par défaut.
- Quotas de l'API Calendar si OAuth : 10 000 req/min/projet, 600 req/min/utilisateur/projet — jamais le facteur limitant.
