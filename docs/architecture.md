### Layers

```
                 settings page (HTML/CSS/JS, ~14 KB gzip)            ← web/            on main
                          │  REST (docs/api-reglages.md)
 ┌────────────────────────┴────────────────────────────────────────────┐
 │ application (main/)  a “Bonjour” screen today; later                │  on main
 │ clock, weather, assistant, settings                                 │  (“Bonjour” only)
 ├─────────────────────────────────────────────────────────────────────┤
 │ pure core (components/core/)  standard C++, no ESP-IDF              │  weather, time,
 │ tables, formats, states, protocols — testable on the PC             │  assistant: on main
 ├─────────────────────────────────────────────────────────────────────┤
 │ board interface (components/board_api/include/board.h, pure C)      │  on main
 ├──────────────────────────────┬──────────────────────────────────────┤
 │ bsp_tab5  (boards/tab5/)     │ bsp_waveshare_7b (boards/…)          │  Tab5: on main
 │ display, touch, expander     │ EK79007, GT911, ES8311/ES7210        │  7B: written, not tested
 └──────────────────────────────┴──────────────────────────────────────┘
        ESP-IDF 5.5.5 · LVGL 9.5 + esp_lvgl_port · ESP32-P4 (+ C6 for Wi-Fi)
```

Rules that hold it together ([AGENTS.md](../AGENTS.md)): the core includes nothing from ESP-IDF; one board = one folder; no `if (tab5)` in the application; errors as `esp_err_t` at the boundaries, no exceptions; no API key readable anywhere.

### Build

`tools/idf.ps1` calls `idf.py` of the ESP-IDF 5.5.5 that ESPHome installed on the author's PC, with the Python of its environment and the `PATH` of the tools (ESPHome's `export.ps1` does not work: [troubleshooting](depannage.md#tools-and-build)); where the script looks for that ESP-IDF is written at its top. The board is chosen by the CMake variable `BOARD` (`tab5` by default). Only one build at a time on the PC, `CMAKE_BUILD_PARALLEL_LEVEL=4`.

Chip settings live in `boards/<board>/sdkconfig.defaults.board`, never in the shared `sdkconfig.defaults`. After any change, delete `sdkconfig` and run `set-target` again: the defaults are only read again for a fresh `sdkconfig`.

### Partitions of the Tab5 (16 MB)

`otadata` 0x9000 · `phy_init` 0xb000 · `ota_0` 0x10000 (4 MB) · `ota_1` 0x410000 (4 MB) · `nvs` 0x810000 · `esphome_nvs` 0xf90000 (left intact: a return to ESPHome does not lose the tablet's settings). Update through the page with automatic rollback (`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`, planned).

### Planned data flows

- **Time**: SNTP → UTC seconds → POSIX TZ rule of the chosen time zone (kept in NVS) → local date and time in French.
- **Weather**: settings (place chosen by the page, `zone_ecrire`) → minimal Open-Meteo request over HTTPS every 15 min (task `meteo_client.cpp`) → parsing by the core → cache in NVS → `meteo_etat_lire()` → screen; offline, the last weather stays, with the mention “stale” (`perime`). Seen on the Tab5 ST7121 on 06/11/2026 (first answer, state back from the cache after a software restart, second request 15 min later); Wi-Fi cut, power cut and change of place **not tested** (see [mesures/meteo.md](mesures/meteo.md)).
- **Assistant**: wake word on the device → STT → streamed LLM → TTS, each one an independent OpenAI-compatible service, local or cloud ([ADR-0002](decisions/0002-assistant-vocal-en-cascade.md)).
- **Settings**: phone → page served by the device → REST API protected by a token shown on the screen → NVS. An API key is written, never read back.

### Compiler

`tools/idf.ps1` appelle `idf.py` de l'ESP-IDF 5.5.5 qu'ESPHome a installé sur le PC de l'auteur, avec le Python de son environnement et le `PATH` des outils (`export.ps1` d'ESPHome ne marche pas : [dépannage](depannage.md#outils-et-compilation)) ; l'endroit où le script cherche cet ESP-IDF est écrit en tête du script. La carte se choisit par la variable CMake `BOARD` (`tab5` par défaut). Une seule compilation à la fois sur le PC, `CMAKE_BUILD_PARALLEL_LEVEL=4`.

Les réglages de puce vivent dans `boards/<carte>/sdkconfig.defaults.board`, jamais dans le `sdkconfig.defaults` commun. Après toute modification, supprimer `sdkconfig` puis relancer `set-target` : les valeurs par défaut ne sont relues que sur un `sdkconfig` neuf.

### Partitions du Tab5 (16 Mo)

`otadata` 0x9000 · `phy_init` 0xb000 · `ota_0` 0x10000 (4 Mo) · `ota_1` 0x410000 (4 Mo) · `nvs` 0x810000 · `esphome_nvs` 0xf90000 (laissée intacte : un retour à ESPHome ne perd pas les réglages de la tablette). Mise à jour par la page avec retour arrière automatique (`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`, prévu).

### Flux de données prévus

- **Heure** : SNTP → secondes UTC → règle POSIX TZ du fuseau choisi (gardé en NVS) → date et heure locales en français.
- **Météo** : réglages (lieu choisi par la page, `zone_ecrire`) → requête Open-Meteo minimale en HTTPS toutes les 15 min (tâche `meteo_client.cpp`) → lecture par le noyau → cache en NVS → `meteo_etat_lire()` → écran ; hors ligne, la dernière météo reste avec la mention « périmée » (`perime`). Vu sur le Tab5 ST7121 le 06/11/2026 (première réponse, état revenu du cache après un redémarrage logiciel, deuxième requête 15 min plus tard) ; Wi-Fi coupé, coupure de courant et changement de lieu **non testés** (voir [mesures/meteo.md](mesures/meteo.md)).
- **Assistant** : mot d'activation sur l'appareil → STT → LLM en flux → TTS, chacun un service OpenAI-compatible indépendant, local ou cloud ([ADR-0002](decisions/0002-assistant-vocal-en-cascade.md)).
- **Réglages** : téléphone → page servie par l'appareil → API REST protégée par un jeton affiché à l'écran → NVS. Une clé API s'écrit, ne se relit jamais.
